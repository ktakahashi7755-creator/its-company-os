# Familink 設計原則（正本）

> 維持責任：CPO_Product_AI ／ CTO_Technology。実装は常にこれに従う。

## 技術スタック
React + TypeScript + Vite + Tailwind CSS / Supabase（DB・認証・ストレージ・RLS） / AIアシスタント Hoku。

## 絶対原則
1. **DBスキーマ先行**：機能の前にテーブル・カラム・リレーション・RLSを設計。UIはスキーマに従う。
2. **認証情報を代行しない**：パスワード・認証コードは本人入力。
3. **家族スコープ＋RLS**：主要テーブルは family_id を必須にしRLSで縛る。体調などセンシティブは特に厳格。

## デザイン
- 装飾的な絵文字は使わない
- アイコンはライン系（line-art）
- 落ち着いた配色（calm palette）
- 余白を活かす
- コピーは簡潔な日本語
- ライトモードでも崩れない（共有時の表示安定）

## Hoku（AIアシスタント）
家族をそっと手伝う案内役。出しゃばらない。やさしく簡潔な日本語。認証情報は扱わない／代行しない。

## データモデルの留意点
- 全主要テーブルに id(uuid)/created_at/updated_at、家族スコープは family_id。
- 物理削除より論理削除（deleted_at）を検討。
- カレンダーは繰り返し（recurrence）を最初に設計。OCR結果は下書き→本人確認で昇格。
