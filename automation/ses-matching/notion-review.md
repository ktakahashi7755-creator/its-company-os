# 代表レビュー面：Notion 設計

代表（オーナー）が**Notionの1つのデータベース**で提案候補を確認し、承認/見送りを判断する。
AIが生成した提案候補はこのDBに行として自動追加され、代表は「要確認」ビューを上から捌く。
**送信はNotion上では行わない**（承認後、ITSセールスから手動送信）。

## なぜNotion

- 代表がスマホ/PCどこからでも同じ面を見られる。行ごとにステータス管理・履歴が残る。
- 既存の朝会自動化（`../run_board_meeting.py`）がNotion投稿の仕組みを持つ＝流用しやすい。

## データベース：「SES提案レビュー（ITS）」

| プロパティ | 型 | 内容 |
|---|---|---|
| 案件×要員 | タイトル | 「遊技機NW/Sec × K.S」など |
| スキルシート（原本） | ファイル | **Excel/PDFの原本を添付**（ここからDL）。要員収集ケースで使用 → `skillsheet-intake.md` |
| スキル要約 | テキスト | AIが原本から生成した「スキル感」要約（`skillsheet-intake.md` の様式） |
| 面談通過可能性 | セレクト | 🟢高 / 🟡中 / ⚪低 |
| スコア | 数値 | 0–100（`scoring.md`） |
| 単価枠 | セレクト | ①経験者 / ②上流PL 等 |
| 想定粗利 | テキスト | 例「+11万/月」 |
| 鮮度 | テキスト | 配信日＋経過日（例 07-10・1日） |
| 商流 | セレクト | 直請可 / 要確認 / 多重NG |
| ステータス | セレクト | **未確認 → 承認 → 送信済 → 面談化 / 見送り** |
| 配信元・会社名 | テキスト | 例：インテレクト株式会社／ルートゼロ株式会社（受信メールから） |
| 担当者名 | テキスト | 宛名に使う（「〔会社名〕〔担当者名〕さま」）。不明なら「ご担当者」 |
| 宛先(To) | テキスト | **担当者の実アドレスをそのまま**。配信リストのみなら「要・宛先確認」 |
| 送信元(From) | テキスト | **sales@its-tokyo.com 固定**（REOorGA不可） |
| 提案下書き | テキスト（本文） | AI生成の提案メール本文 |
| 出典 | テキスト | REOorGA受信日時・件名 |
| 確認メモ | テキスト | 見送り理由 / 交渉メモ（採点の学習材料） |

## ビュー（3つ）

1. **要確認**（既定）：`ステータス=未確認` を `スコア降順`。代表はここを上から捌く。
2. **ボード**：`ステータス`でカンバン（未確認→承認→送信済→面談化／見送り）。進捗が一目。
3. **本命**：`面談通過可能性=高` のみ。時間がない日はここだけ。

## 運用フロー

1. AI実行（接続後は定期）→ 提案候補を `ステータス=未確認` で行追加。
2. 代表が「要確認」ビューを開く → カードを開き**提案下書き**を読む。
3. OK → `ステータス=承認`。下書きをコピーし **ITSセールスから手動送信** → `送信済`。
4. NG → `ステータス=見送り`＋確認メモに理由（採点精度が上がる）。
5. 面談に進んだら `面談化`。結果は `../../data/pipeline.md` と `../../docs/kpi.md` に反映。

## 接続（あとで）

1. https://www.notion.so/my-integrations で内部インテグレーション作成 → `NOTION_TOKEN`。
2. 上記DBを作り、そのインテグレーションを「接続」で共有。DBのIDを控える。
3. 定期実行のAI（GitHub Actions・`run_board_meeting.py`同型）がDBへ行を追加する実装を足す。
   - 併せて `digests/digest-YYYYMMDD.md` もリポジトリに残す（バックアップ・履歴）。

## ⚠️ ガードレール（再掲）

- 送信元は**ITSセールス固定**。REOorGA受信アドレスからは送らない（`sources.md`）。
- 送信は必ず**代表の承認後・手動**。NotionのステータスはAIが勝手に「送信済」にしない。
