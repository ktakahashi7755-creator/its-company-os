# スキルシート取り込み（Excel／PDF）＆要約

ITS自社案件に要員を集めるとき、スキルシートは **Excel（.xlsx）／PDF 添付**で届く。
これを「**原本を開ける＋中身をAIが要約する**」形にして、代表がレビュー面で判断できるようにする。

## ⚠️ 個人情報の扱い（重要）

- スキルシートは氏名・経歴・連絡先など**個人情報**を含む。
- **原本をgitリポジトリに直接コミットしない**（履歴に残り消せない）。
  - 原本の置き場：**Notionのファイル添付**（レビューDBの「スキルシート」プロパティ）または Google Drive 等、
    アクセス管理された場所。
  - リポジトリに残すのは**AI要約（イニシャル化）＋参照リンク**のみ。
- ローカル作業用の一時置き場 `../../data/skillsheets/` は **.gitignore 済み**（原本はコミットされない）。

## コスト最適化：マッチしてから読む（重要）

**添付スキルシートは全件読まない。** まず安いテキストでマッチし、**マッチした要員だけ**添付を読む。

- 要員配信メールには必ず**サマリー文**があるので、**サマリー＋件名**で必須スキル充足を判定（添付は開かない）。
- 面談通過可能性が**高/中**になった要員のみ、そのメールを**UIDで再取得して添付（PDF/Excel）を初めて読み込み**、
  スキル要約を生成してダイジェスト／Notionに反映する。
- これで「重い添付を無駄に読む」ことがなくなり、API・処理コストを最小化できる（実装：`run_ses_matching.py`
  の `enrich_skillsheets()`／`extract_skillsheets()`）。
- 案件配信（ITS要員を当てる側）は**添付が基本無い**ため、**案件概要（本文）**でマッチする。

## 取り込みフロー

1. **一次判定（テキストのみ・安い）**：サマリー＋件名（案件は案件概要）でマッチ。**添付は読まない。**
2. **抽出（マッチ後のみ・高い）**：高/中の要員だけ添付を再取得し、下記で本文抽出。
   - Excel → 表を読み取り（自動化では `openpyxl`）。シート複数・結合セルに注意。
   - PDF（テキスト）→ テキスト抽出（`pdfplumber`/`pymupdf`）。
   - PDF（スキャン画像）→ **OCRが必要**。読めない場合は「要OCR・原本参照」と明記し捏造しない。
3. **要約生成**：下記フォーマットで「スキル感」を要約。案件必須要件への適合も判定。
4. **格納**：原本＝Notion添付、要約＝レビューDBの「スキル要約」＋ `templates/skillsheet.md` 形式で整形も可。

## スキル要約フォーマット（AI出力）

```
【スキル要約】〔イニシャル〕／〔主要領域〕／経験〔N〕年
・強み：〔案件必須に直結する実績を具体で。製品名・規模・役割〕
・上流：〔PL/PM・要件定義・提案改善の有無〕
・環境：〔OS/仮想/NW機器などの対応範囲〕
・単価：〔希望〕（枠：①/② 判定・粗利可否）
・案件適合：〔必須充足の可否〕→ 面談通過可能性〔高/中/低〕
・確認点：〔商流/稼働/不足スキルなど面談前に潰す点〕
```

> 整形版が要るときは `../../templates/skillsheet.md`（ITS標準スキルシート様式）に落とす。
> **嘘は書かない。** 原本に無い経歴・数字を補完しない（不明は空欄）。

## レビューDBへの反映（`notion-review.md`）

要員収集の行には次を追加：
- **スキルシート（原本）**：ファイル添付（Notion）／ダウンロード可
- **スキル要約**：上記フォーマットのテキスト
- 併せて スコア・面談通過可能性・単価枠 は `scoring.md` で採点。
