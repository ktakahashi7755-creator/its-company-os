# SES 案件×要員 自動マッチング（手順書）

配信メール／SNSで流れてくる **要員（エンジニア）** を、保有案件に対して自動採点し、
**手元に「要員サマリー＋スキルシート＋マッチ度＋返信下書き」を1ファイルで集約**する仕組み。

> 上位方針は `../../CLAUDE.md`、営業の型は `../../skills/ses-sales/SKILL.md` を参照。
> Phase 0の原則：**収集〜集約までは自動、要員の最終チェックと提案送信は代表（人間）**。

## 自動化する範囲としない範囲（固定）

| 工程 | 誰 |
|---|---|
| ①収集（配信メール／SNSから要員を拾う） | 自動（Gmail接続後）／当面は手動貼付 |
| ②正規化（構造化して台帳化） | 自動 |
| ③採点（案件×要員をルーブリックで100点） | 自動 |
| ④集約（日次ダイジェスト生成） | 自動 |
| ⑤要員チェック・マッチ度の最終確認 | **代表（目視）** |
| ⑥個別返信・提案送信 | **代表が承認 → 手動送信**（AIは下書きまで） |

**⑥の自動送信はやらない。** 配信メール自動返信／SNS自動DMはスパム判定・アカウント凍結・
元請け直の商流毀損リスクが高い。ここは必ず人間がボタンを押す。

## ファイル構成

```
automation/ses-matching/
├── README.md                 ← この手順書
├── 案件_20260711_遊技機NWSec.md  ← 案件定義＋採点ルーブリック（案件ごとに1枚）
├── inbox.example.md          ← 配信メール本文を貼る雛形（inbox.md にコピーして使う）
├── reply-template.md         ← 個別返信（提案）テンプレ
└── digests/                  ← 生成された日次ダイジェストの置き場
```

## 回し方（当面＝半自動。Gmail未接続でも今日から動く）

1. 配信メール／SNSで拾った **要員1件＝1ブロック** を `inbox.example.md` を複製した
   `inbox.md` に貼り付ける（本文まるごとでOK。整形はAIがやる）。
2. Claude Code / Claude に「**ses-matching のダイジェストを作って**」と依頼。
   AIは各要員を②正規化③採点し、対象案件ごとに `digests/digest-YYYYMMDD.md` を生成する。
3. 代表は **ダイジェスト1ファイルだけ** を目視。本命に✓、見送りは理由を一言（採点の学習材料）。
4. ✓の要員は、ダイジェスト内の**返信下書き**を最終確認して、**元の配信メールに個別返信**（送信は手動）。
5. 結果（通過／面談／見送り）を `../../data/pipeline.md` に反映。採点精度が上がる。

> 日付が使えない実行環境では、AIに「今日は YYYY-MM-DD」と伝えるとダイジェスト名が正しく付く。

## 完全自動化への拡張（後追い）

- **① 収集の自動化**：Gmail等をMCP接続 →「SES/人材配信」ラベルへ自動仕分け →
  スケジュール実行のAIセッションが未読を読み `inbox.md` を自動生成。
  ※現在メール系コネクタは**未接続**（`ListConnectors` が空）。接続後にここを有効化する。
- **SNS収集**：X APIは有料（Basic 約$100/月）。母集団は広いがToS/凍結管理が要るため、
  メール自動化で効果検証してから追加する（Phase 0では固定費を先送り）。
- **定期実行**：Gmail接続後、既存の GitHub Actions 方式（`../run_board_meeting.py` と同型）で
  毎朝ダイジェストを自動生成→Notion/LINE通知、まで拡張できる。

## ガードレール

- **「外国籍不可」等の属性条件は自動フィルタに組み込まない**（法令グレーの論点）。
  クライアント要件として案件定義に注記するに留め、取り扱いは代表判断＋必要なら専門家確認。
- 商流制約（多重NG・直請け要件）は要員ごとに必ず確認。元請け直は特に要注意。
- スキルシートに嘘は書かない。見せ方（強調順）の最適化のみ。
- 粗利死守ライン ¥8万/月。割るなら長期更新・次案件優先などの条件で取り返す。
