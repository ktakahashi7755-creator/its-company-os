# knowledge/ — 代表ノウハウ層（マッチング精度の燃料）

高橋（代表）が持つSESの「勘・型・地雷リスト」を構造化して置く場所。
ここに注いだノウハウが `automation/ses-matching/` のマッチング精度に反映される。

> 上位方針は `../CLAUDE.md`、営業の型は `../skills/ses-sales/SKILL.md`、
> マッチング実装は `../automation/ses-matching/` を参照。

## これが何のためにあるか（フライホイール）

```
① 代表がノウハウを注ぐ（ヒアリングシート.md にしゃべる／書く）
        ↓ AIがコンパイル（決定論で config へ反映・数字は捏造しない）
② scoring.md / active-case.json / プレフィルタ語彙 / 返信テンプレ が賢くなる
        ↓
③ 24時間 案件×要員を自動マッチング → 本命＋提案下書きが sales@ Drafts と Notion に積み上がる
        ↓ 代表は「送るだけ」（送信は常に人間・ガードレール §6）
④ 結果（面談通過/見送り）を記録 → 毎週このノウハウ層へ還流 → ①へ戻り精度が上がる
```

**放っておくほど賢くなる**のが狙い。ノウハウは一度きりでなく、勝ち負けが出るたびに足していく。

## どのノウハウがどこに効くか（コンパイル先マップ）

| ノウハウ（このフォルダ） | 反映先（自動マッチング） | 効き方 |
|---|---|---|
| `01_単価勘.md` | `scoring.md`「単価整合」軸・`active-case.json` の client_rate/engineer_rate_pref・crossmatch の `MARGIN_YEN` | 相場から外れた案件を減点、粗利ラインを死守 |
| `02_商流地雷とBPのクセ.md` | プレフィルタ除外語・`scoring.md`「商流の通りやすさ」軸・要確認フラグ | 地雷案件を早期に落とす／怪しいBPを要確認へ |
| `03_勝ちパターンと目利き.md` | `scoring.md` 必須スキル内訳・本命(85+)判定ガード・SYSTEM_PROMPT | 「通る組合せ」を本命に、「合うが通らない」を中に落とす |
| `04_営業の型と文面.md` | `reply-template.txt`・案件定義の MAIL-BLOCK・署名 | 刺さる件名・冒頭・訴求・反論処理を下書きに反映 |
| `05_供給プール.md` | `../data/partners.md`（常時5名以上） | 総当たりマッチングの供給側の母集団 |
| `06_BP発注元.md` | `../data/bp-list.md` | 需要側（発注元）の母集団・単価/入金サイト |
| `07_NG_代表ルール.md` | 全エンジンのガードレール・除外条件 | 「絶対受けない」を機械的に除外 |
| `08_現行案件の確定値.md` | `active-case.json`・アクティブ案件定義ファイル | いま流している案件の最新の確定値 |

## 使い方（代表）

1. `ヒアリングシート.md` を開く（or この一覧に沿って口頭で伝える）。
2. 分かる所だけ埋める／しゃべる。**分からない数字は空欄でよい**（AIは捏造しない・§6）。
3. AIが該当configへ反映するPRを作る → 代表はマージ（会話ゼロ運用）。
4. 実際に案件が動いたら、結果をこのフォルダへ一言足す（次の精度向上の燃料）。
