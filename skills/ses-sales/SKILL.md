# SES営業スキル

ITS合同会社のキャッシュエンジン。**ブローカー型（協力会社のエンジニアをクライアント商流に乗せ、粗利を取る）が基本。** 代表をSES常駐に溶かさず、案件と人を動かして稼ぐ。

> 前提となる経営原則は `../../CLAUDE.md` を参照。判断は常に「今月の月利益を増やすか」で切る。

## いつ何をするか（ワークフロー）

1. **BP/協力会社を開拓する** → 下記「開拓」へ
2. **案件が来た** → 「案件分析」→「マッチング判定」→「提案作成」
3. **商談した** → 「振り返り」で成約率を改善
4. **数値を見る** → `../../docs/kpi.md` を更新し、ファネルの詰まりを特定

---

## 1. 開拓（BP・協力会社）

### BP（発注元）開拓
- 優先：代表の通信・IT人脈 → 既存BPの紹介 → SES案件紹介サイト → SNS/勉強会。
- **深さ優先**：新規10社より、信頼できる1社で複数案件を取る方が粗利も効率も上。
- 1社開拓したら「常時どんな案件があるか」「商流の深さ（元請/二次請け）」「単価レンジ」「入金サイト」を必ず聞く。

### 協力会社（エンジニア供給元）開拓
- 提案可能な人材プールを常に5名以上維持。
- 各エンジニアについて：スキル / 経験年数 / 希望単価 / 稼働可能日 / 商流上の制約（多重NG等）を把握。

開拓の進捗は `../../data/bp-list.md` `../../data/partners.md` に記録する。

## 2. 案件分析

案件が来たら、まず次を構造化して評価する。

```
案件名：
必須スキル：       歓迎スキル：
単価（クライアント提示）：     商流の位置（元請/n次請け）：
稼働開始：     期間：     稼働形態（常駐/リモート/ハイブリッド）：
入金サイト：     精算幅（時間）：
```

評価軸：
- **粗利の妥当性**：提示単価 − エンジニアへの支払 = 粗利。¥8万/月を下回るなら理由を明確に（戦略的に取る場合のみ）。
- **商流の深さ**：深いほど粗利は薄い。元請に近いほど良い。
- **資金繰り**：入金サイトが長い案件は資金ショートに注意（`../skills/finance-cfo`）。
- **更新性**：長期・更新前提の案件はLTVが高い。優先。

## 3. マッチング判定

案件 × 候補エンジニアの適合度を判定する。AIは下書きまで、最終判断は代表。

> **配信の自動マッチングは `../../automation/ses-matching/` に実装。**
> REOorGA配信（受信専用）→ 鮮度5日で網羅 → `scoring.md` で面談通過可能性を採点 →
> Notion「SES提案レビュー」に集約 → 代表承認後にITSセールスから手動送信。
> 採点・除外・ガードレールはそのREADMEに従う。

| 観点 | 確認 |
|---|---|
| 必須スキル充足 | 必須を満たすか（歓迎は加点） |
| 単価整合 | エンジニア希望 ≤ クライアント単価 − 目標粗利 |
| 稼働タイミング | 開始日が合うか |
| 商流制約 | 多重NG・直請け要件などに抵触しないか |
| 通勤/リモート | 条件が合うか |

**出力：適合度（高/中/低）＋ 提案順位 ＋ 訴求すべき強み ＋ 懸念点とフォロー案。**

## 4. 提案作成

`../../templates/proposal-ses.md` と `../../templates/skillsheet.md` を使う。

スキルシート整形のコツ：
- 案件の必須スキルに合わせて経歴の見せ方を最適化（嘘は書かない、強調順を変える）。
- 冒頭3行で「この案件になぜ合うか」を要約。
- 実績は数字（規模・期間・役割）で。
- 不足スキルがある場合は、近接スキル・キャッチアップ可能性で補強。

提案メールは簡潔に：誰を/なぜ合うか/単価/稼働可能日/スキルシート添付、の5点。

## 5. 商談の振り返り（成約率改善）

商談後は毎回これを回す：
```
案件：     候補：     結果（通過/見送り/保留）：
クライアントの反応・懸念：
こちらの提案の弱かった点：
次に同種案件で変えること：
```
- 見送りが続くなら「提案→面談率」と「面談→成約率」のどちらが低いかを特定し、原因（BPの質/スキルシート/単価/マッチ精度）に手を打つ。

---

## 6. KPIと拡大戦略

- ファネルKPIは `../../docs/kpi.md`。毎夕記録・毎週レビュー。
- 拡大順序：**(1)深さ＝1社で複数案件 → (2)幅＝BP増 → (3)質＝高粗利商流へ移動。**
- 稼働中エンジニアの**契約更新月の1ヶ月前に必ず接触**（離脱・空白期間の防止）。

詳細な営業トークの型・テンプレ文面は `references/playbook.md` を参照。
