# AI受託 デリバリー詳細（reference）

## 提案書の構成（推奨）
1. 現状の課題（顧客の言葉で）
2. あるべき姿
3. 打ち手（なぜAIか／AIでない部分も正直に）
4. スコープ（やること/やらないこと）
5. 進め方（PoC→本開発→保守の3段）
6. 体制・スケジュール
7. 見積（段階別）
8. 期待効果（定量できる範囲で。誇張しない）

## PoCの進め方
- 目的：小さく作って「効果が出るか」を2〜4週間で検証。
- 成功基準を先に数値で合意（例：問い合わせ一次対応の自動化率◯%）。
- PoCで筋が悪ければ正直に撤退提案（信頼を守る方が長期で得）。

## 見積の内訳例
| 項目 | 内容 |
|---|---|
| 要件定義 | ◯人日 |
| 開発 | ◯人日 |
| テスト/調整 | ◯人日 |
| API/ツール費 | 従量 or 実費 |
| バッファ | 工数の15〜20% |
| 保守（月額） | 運用・改善・問い合わせ対応 |
