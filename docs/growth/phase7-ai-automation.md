# P7：AI化・自動化 — システム構成とAI分担

> 作成日：2026/7/3　ステータス：暫定確定
> 原則：**高橋に残すのは「営業（人と会う）・最終決断・人間関係」だけ。** それ以外はAI＋仕組みへ。新規SaaS課金は原則追加しない（固定費）。

---

## 1. AI組織（誰が何をやるか）

既存の `skills/` がそのままAI組織図。人を雇う前に、まずここに仕事を割り当てる。

| 役割 | 担当AI（スキル） | 具体タスク |
|---|---|---|
| 経営会議・優先順位 | `management-meeting`＋`executives/`（10 CXO） | 毎朝の一手決定・重要判断は`board-meeting`へ |
| 経理・決算補助 | `tax-compliance` `finance-cfo` | 明細4分類・納期限管理・資金繰り表（※申告の最終判断は税理士） |
| SES営業事務 | `ses-sales` `ses-ops` | スキルシート整形・提案文生成・案件分析・KPI集計 |
| 商品営業事務 | `ai-jutaku`＋P5テンプレ群 | 診断レポート生成・提案書生成・見積作成 |
| 開発 | `familink-dev`＋Claude Code | Familink実装・受託実装・自社HP |
| 進捗・記録 | 本プロジェクト（P6） | kpi記録の催促・週次レビュー草案 |

## 2. 自動化する業務（優先順）

| 優先 | 業務 | 自動化の形 | 効果 |
|---|---|---|---|
| 1 | スキルシート整形・提案文 | 原本を渡す→AIが`templates/skillsheet.md`形式に即整形 | SES提案の即日化＝成約率 |
| 2 | 診断レポート・提案書生成 | 商談メモ→`templates/diagnosis-report.md`等に自動流し込み | 商談当日送付 |
| 3 | 銀行・クレカ明細の4分類 | CSV→AIが仕分け案→高橋が確認のみ（`finance/`運用） | 決算・月次の時間を1/5に |
| 4 | KPI集計・週次レビュー草案 | `data/pipeline.md`から自動集計→`kpi-weekly.md`草案 | レビューを30分→10分 |
| 5 | 再点火メッセージの下書き | 相手情報→パーソナライズ済み下書きを一括生成 | 接点数の上限を引き上げ |
| 6 | 請求書・入金予定表 | 月末に稼働一覧→請求書ドラフト＋入金/支払カレンダー | 入金漏れ・ショート防止 |

**自動化しないもの**：商談そのもの・単価交渉・紹介依頼（人間関係は高橋）。顧客の認証情報を扱う作業（ガードレール）。

## 4. Notion構成（顧客・対外用と日常ビュー）

Gitが正本、Notionは「見る場所」。二重管理を避けるため、Notionには**貼り付け運用**のみ。

```
ITS Notion
├── 🏠 ダッシュボード（今週の一手・KPIサマリー貼付）
├── 📊 営業ボード（pipeline.mdの内容をボードビューで）
├── 📁 顧客ページ（顧客ごと：議事メモ・送付資料リンク）
├── 📄 提案書・診断レポート置き場（PDF共有用）
└── 🔒 経営（business-plan/kpi/roadmapの貼付。docs/が正本）
```

## 6. Claude Codeプロジェクト構成

- **its-company-os（このワークスペース）**：経営・営業・経理のすべて。CLAUDE.mdが頭脳、skills/が部門。
- **familink**：開発専用。夜はこちらだけを開く（経営タスクに気を散らさない）。
- **受託リポジトリ**：案件ごとにCLAUDE.md（スコープ・やらないこと・顧客固有ルール）を必ず置く——スコープクリープ防止を仕組みで担保。
