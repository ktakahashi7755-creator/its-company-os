# 0002 — 京楽（遊技機メーカー）案件のスコープ改定とマッチング再稼働

## 決定タイトル
京楽案件を「NW×セキュリティの上流PL」から「情シスインフラPL＝サーバ×NW両刀」へ改定し、SES自動マッチングを新スコープで再稼働する。

## 日付
2026-07-22

## 状況 / 背景
- 初版スコープ（ネットワーク×セキュリティ両刀の上流PL）で募集し、**KNさんがオファーを獲得**（初版は充足）。
- 直後にクライアントから**スコープ見直し**が入り、自動マッチング・自動下書きを一時停止（2026-07-21）。
- 2026-07-22、クライアントより**正式版の案件票**を受領。案件の性格が大きく変わった：
  - 必須の両刀が「NW×セキュリティ」→「**サーバ×ネットワーク**の構築・運用ディレクション」へ。
  - **セキュリティ（EDR初動等）は必須→歓迎**に降格（横断業務の一部）。
  - **事業会社の情シス実務／BPO経験**と**2〜5名の小規模チームのPL/リーダー・進捗/品質管理**が新たに必須。
  - 年齢目安 〜45歳→**40歳程度まで**、単価 **〜100万**（支払92万以下で粗利¥8万確保）、8月開始、恵比寿・週2出社。

## 選択肢
- **A：正式版を全面反映し、マッチング精度（両刀ゲート・採点）をサーバ×NWへ作り替えて再稼働**（採用）。
- B：案件定義だけ更新し、マッチングは停止のまま代表が手動運用。
- C：初版で充足済みのため本案件はクローズし、新規案件として別IDで立ち上げる。

## 決定
**A を採用。** 理由（経営4原則で説明）：
- **月利益**：SESはキャッシュ核。元請直・単価〜100万の案件を自動マッチングで供給し続ける方が、
  代表の手作業より粗利効率が高い（ブローカー型・代表を常駐に溶かさない原則）。
- **固定費**：追加費用ゼロ（既存のGitHub Actions＋受信専用IMAPで回る）。回収期間の論点なし。
- **代表の時間**：採点・下書きはAIが担い、代表は最終送信と面談だけに集中（原則3）。
- 案件IDは継続（`20260711_遊技機NWSec`）。KNさんは初版で充足済みのため、新スコープでは**別ポジションとして集め直す**。

### 実施内容（要点）
- 案件定義を正式版 rev.2026-07-22b へ全面反映（業務内容・技術環境・補足確認項目・単価確定）。
- `run_ses_matching.py` の両刀ゲート `PREFILTER_GROUPS` を「サーバ群×NW群」へ、SYSTEM_PROMPT／`scoring.md` を
  サーバ×NW両刀＋情シス/PL必須・セキュリティ歓迎・単価アンカー支払92万以下へ更新。
- eval fixtures を新スコープへ作り直し、**決定論15ステージ全緑（`--stage all`・exit 0）／プレフィルタ F1=1.00**。
- 案件ファイルを稼働位置へ移動し、両ワークフローの `schedule:` を再有効化。

## 想定リスクと撤退条件
- **供給側リスク**：支払92万以下でサーバ×NW両刀＋情シス/PLの供給が薄い可能性。
  → 初回ダイジェストで本命ゼロが続くなら、BP/協力会社へ単価再交渉、または歓迎要件で候補幅を広げる。
- **属性選別（法令グレー）**：年齢40歳程度まで・外国籍不可はクライアント条件。**ITS側は自動除外せずフラグ運用**、
  配信文面には年齢を記載しない（従来慣行）。明記可否は代表判断として保留。→ 専門家確認が要れば上げる。
- **競業・利益相反**：プロバイド（SES）との棲み分けは継続確認（CLAUDE.md §1）。
- **段階②（LLM採点）**：ローカルではAPIキー未設定で未実測。CI（キー有）で毎回実測されるため、
  初回実測の帯一致が低ければ `scoring.md` の重みを再調整する。

## 結果（追記）
- **2026-07-22 段階②（LLM採点）初回実測**（PR #42 の eval CI・OpenAI gpt-4o-mini・fixtures 13件）：
  - 本命(85+)一致率 **12/13 = 0.92**（良好）。帯一致率 **8/13 = 0.62**。
  - 帯ミスは**全て同方向＝過剰除外**（S02/S06/S07/S08/S09 が期待「中/高/flag」→実際「除外」）。
    特に S07（年齢58歳）を除外＝**年齢で自動除外しない原則の違反**、S08（完全両刀＋情シス＋PL）の除外＝取りこぼし。
  - **原因**：直前に追加した否定・希薄化の採点補正が「除外」側に効きすぎ、中band（両刀成立だが一軸が薄い/商流2次）を潰していた。
  - **対策（同PRで反映）**：SYSTEM_PROMPT／`scoring.md` に「**除外はハード条件（両刀不成立・単価超過・鮮度切れ・多重NG）のみ**、
    それ以外は『中』で減点」「**両刀＋情シス実務があれば最低『中(60+)』**」「年齢・国籍はflagのみ」を明記＝中band保護。
  - **再計測（同PR・中band保護プロンプト適用後）**：帯一致 **8/13 = 0.62（変化なし）**、本命 **12/13 = 0.92**。
    プロンプトを変えても**出力がバイト単位で同一**（同じ5件が除外）＝**gpt-4o-mini の能力上限**。プロンプト調整では中bandの
    過剰除外は動かせないと判明（プロンプト過学習を避けるため調整ループはここで停止）。
  - **結論**：①**自動下書きする本命層(85+)は 0.92 で十分**（`is_pickup` の決定論ガードも併用＝年齢flag等は自動下書きに載らない）。
    ②中band（参考tier）の過剰除外は**モデル起因**で、改善は**上位モデル採用＝変動費**の判断＝代表マター。
    中band保護プロンプトは上位モデルなら効くため残置（害はない）。
  - **コスト対応**：eval CI の段階②LLM計測を毎pushから**手動実行(workflow_dispatch)限定**に変更（Phase 0のコスト最優先）。
    決定論15ステージのゲートは引き続き全pushで自動。
  - **gpt-4oで1回計測（代表承認・PR #42 eval CI）**：帯一致 **10/13 = 0.77**（mini 0.62→+0.15）、本命 **13/13 = 1.00**（mini 0.92→満点）。
    個別では **S07（年齢58歳）が「除外」→「flag」に是正＝年齢自動除外しない原則を回復**、S08（完全両刀本命）が「除外」→「高」に是正。
    残る帯ミスは S02/S09（両刀成立だが情シス/PL薄い・商流2次の境界＝中/除外の判断割れ）と S06（中↔高の1段ズレ）で、判断が割れる範囲。
  - **推奨**：本番採点を **gpt-4o に採用**。理由＝①本命(自動下書き)が満点で面談化に直結、②**年齢flagガードレールの回復は原則遵守（コンプラ）事項**、
    ③日次の実マッチは少数のため変動費の絶対額は小さい（Phase 0の固定費最優先には抵触しにくい）。→ 代表承認後 `vars.OPENAI_MODEL=gpt-4o` を設定。
  - **代表判断待ち**：上記の本番gpt-4o採用の可否。
