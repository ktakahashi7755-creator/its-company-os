## 1. 何を売るか（入口商品3つ＋ストック）

Claude Codeで制作工数を1/5〜1/10に圧縮できるのが唯一かつ最大の武器。
「安くて速いのに品質が高い」を成立させ、低価格帯でも粗利を確保する。

| # | 商品 | 価格（提案値） | 納期 | 中身 |
|---|---|---|---|---|
| A | LP・1ページサイト | ¥30,000〜¥80,000 | 3〜5営業日 | レスポンシブ1ページ、フォーム、独自ドメイン設定込み |
| B | コーポレートサイト | ¥100,000〜¥250,000 | 2〜3週間 | 5ページ前後、問い合わせフォーム、基本SEO |
| C | 簡易システム・業務ツール | ¥150,000〜（要見積） | 案件次第 | 予約/フォーム/管理画面/スプレッドシート自動化/AIチャットボット |
| ＋ | 保守・更新（ストック） | 月額¥5,000〜¥20,000 | — | 軽微修正、監視、月1回の更新枠 |

- **実績づくり期（最初の3件まで）**：Aを¥30,000〜¥50,000で受けてよい。ただし必ず「実績掲載許可」を交換条件にする。
- 価格は提案値。案件ごとに見直してよいが、**赤字受注（時給換算¥2,000未満）はしない**。
- Cは`skills/ai-jutaku`のワークフローに接続（ヒアリング→スコープ→見積）。

### 技術スタック（固定してテンプレ化＝納品速度が資産になる）
- サイト：静的HTML/CSS（or Astro）＋ 必要ならReact。ホスティングはGitHub Pages / Cloudflare Pages（**無料＝固定費ゼロ**）
- フォーム：Googleフォーム or Formspree無料枠
- 簡易システム：React + Supabase（Familinkの技術資産を再利用）

## 3. 受注ルール（ガードレール・厳守）

1. **前金50%以上**（初回取引は原則。クラウドソーシングは仮払い制度があるのでそのままでよい）
2. **スコープを書面で合意**してから着手（`templates/proposal-web.md`）。修正は2回まで、以降は追加見積
3. **Claude Codeで作り切れる案件だけ受ける**。CMS大規模カスタマイズ・レガシー改修・常駐要求は断る
4. 顧客の認証情報（サーバー・ドメイン・SNSのパスワード等）を**代行入力しない**。顧客に入力してもらう（全社共通ガードレール）
5. 入金は**必ずITS法人口座**。個人口座と混在させない（決算・出口の体裁に直結）
6. 固定費を増やさない。有料ツールは案件粗利から回収できる時だけ、単発で
7. **時間上限**：営業活動は1日30分（応募・返信）。制作は夜・週末のFamilink時間から週数時間まで借りる。**8月申告の作業と衝突したら決算が勝つ**

### Week 2〜4 — 応募の運転を回す
- [ ] 毎営業日30分：新着案件に2件応募（週10件）

- [ ] 納品したら`website/`の実績欄に追加、ココナラ等のプロフィールにも反映

### Month 2〜3 — 実績で単価を上げる
- [ ] 実績3件到達 → Aの下限を¥50,000に引き上げ

- [ ] 下請けチャネル（制作会社10社打診）を開始

### 撤退・見直し条件
- 90日で成約0件 → チャネルと価格を取締役会（`skills/board-meeting`）にかけて再設計
- 決算作業が遅延し始めたら受注を一時停止（Phase 0が優先）

## 6. 案件の流れ（受注〜入金）

```
応募/紹介 → ヒアリング（templates/hearing-web.md）
→ 提案・見積（templates/proposal-web.md）→ 前金入金確認
→ 制作（Claude Code）→ 確認・修正2回 → 納品・残金請求
→ 実績掲載許可・レビュー依頼 → 保守月額の提案
→ data/pipeline.md を更新
```

パイプライン管理は `data/pipeline.md` の「Web受託」表で行う。
